## Design decisions

### CSS variables only — via Tailwind arbitrary value syntax
Every colour + radius uses `var(--token)` through Tailwind v4 arbitrary
value syntax: `bg-[var(--accent)]`, `text-[var(--on-accent)]`,
`border-[var(--hairline)]`, `rounded-[var(--radius-input)]`, etc. This is
the most defensive approach — it works regardless of how the `@theme inline`
block maps tokens to utilities, and it's self-documenting (you can see
exactly which token is used at each call site). The globals.css `@theme inline`
block also generates the colour utilities (`bg-accent`, `text-on-accent`,
`bg-surface`, etc.) which the legacy shopkeeper/admin components already
use — both syntaxes coexist.

### Clear status pills use tints, not solid fills
The old `customer/status-pill.tsx` used solid colour fills (bg-warning
text-ink, bg-success text-white, etc.). The Clear language prefers soft
tinted backgrounds with strong status-text colour — every status pill now
uses its `{status}-tint` bg + `{status}-text` pair (e.g.
`bg-[var(--success-tint)] text-[var(--success-text)]`). This reads as
quieter + more premium, and the tints are AA-compliant against their
text colours in both light and dark mode (re-verified in the token
definitions).

### Stepper is minimal bars, not numbered circles
The old `customer/stepper.tsx` was a numbered-circle stepper with a
connector line. The Clear brief explicitly calls for "three 4px bars
(current + done in accent)" — a deliberately minimal progress indicator
with no numbers, no circles, no labels. The customer checkout flow is
short enough (3 steps) that the bars alone are sufficient. The component
is generalised to N steps (default 3) so it can serve other sequences.

### Sheet back-gesture close via history sentinel
The brief requires "Escape/back close". Escape is straightforward
(keydown listener). The "back" is the mobile back gesture / browser back
button — handled by pushing a sentinel `history.pushState` entry when the
sheet opens and listening for `popstate`. When the user hits back, the
sheet closes instead of navigating away. On cleanup, if the user closed
the sheet via Escape/backdrop/Escape (which already fired popstate), the
sentinel is gone; otherwise we pop it via `history.back()` so it doesn't
linger. `pushState` is wrapped in try/catch because it can throw in
sandboxed iframes — in that case Escape + backdrop tap still close.

### Sheet is responsive via useIsMobile, not CSS breakpoints
The sheet's mobile-vs-desktop layout (bottom sheet vs right drawer) is
decided by the existing `useIsMobile` hook (768px breakpoint) rather than
Tailwind responsive prefixes. This is because the slide animation direction
differs (translate-y vs translate-x) and framer-motion variants need a
JS-side decision to pick the right axis — mixing `slide-in-from-bottom`
and `slide-in-from-right` Tailwind utilities would set conflicting custom
properties. The hook returns `false` during SSR, but the sheet starts
closed (`open=false`) so the layout decision only matters post-mount when
the user opens the sheet.

### RadioRow is a group that renders rows from an options array
Rather than exposing a bare `RadioRow` presentational component (which
would force every caller to wire up roving tabindex + arrow-key
navigation), `RadioRowGroup` takes an `options` array and renders the rows
+ handles the full WAI-ARIA radiogroup keyboard pattern internally. This
matches the `SegmentedControl` API shape and is much harder to misuse.
Arrow navigation skips disabled rows.

### Checkbox built on visually-hidden native input
The visible 22px box is a `<span>` sibling to a `sr-only` native
`<input type="checkbox">`. This gives free keyboard support (Space
toggles), form submission, and screen-reader semantics, while the visible
box reflects state via `peer-checked:` utilities. The `peer-focus-visible`
utility adds a 2px accent ring when the hidden input receives keyboard
focus — so the focus affordance is visible even though the input itself
is not.

### Loading state preserves button width
When `loading` is true, the button renders an invisible copy of its full
label + icons (reserving the exact width) plus an absolutely-centred
`Loader2` spinner on top. The button never narrows when the spinner swaps
in, so the layout never shifts. `aria-busy` is set so screen readers
announce the pending state.
