## Design decisions worth flagging

### Stepper
- Display-only — no `onClick` per step. The brief says "you are here",
  not "jump to step". If a future task wants clickable steps, the
  `<li>` can wrap a `<button>` without restructuring.
- Connector line: one absolutely-positioned unfilled track
  (`bg-[var(--color-border-ink-strong)]`, 2px) with an overlaid filled
  segment (`bg-[var(--color-cyan-ink)]`) sized by inline `width` as
  `calc((100% - 64px) * progress)` where `progress = current / (steps.length - 1)`.
  The 64px accounts for the 32px inset on each side so the line spans
  from first circle centre to last circle centre.
- The brief said "thin line (border-ink)"; I used `border-ink-strong`
  (20% ink) instead of `border-ink` (10%) because at 2px the 10%
  variant is nearly invisible on `--color-paper`. If the design lead
  wants the literal 10%, swap the class on the unfilled track span.
- Completed step swaps the number for a `Check` icon (`size-4`). The
  circle is `size-8` (32px) and stays the same size in every state —
  no layout shift.

### SegmentedControl
- Roving tabindex: only the selected option (or the first if no
  match) has `tabindex=0`; the rest are `tabindex=-1`. Arrow Left/Right,
  Arrow Up/Down, Home, and End all move AND select (matching the
  WAI-ARIA radiogroup pattern). Enter/Space are native to `<button>`.
- Active segment lifts off the track with `shadow-[var(--shadow-bar)]`
  + surface bg + ink text. Inactive segments are transparent + muted
  text on the paper trough.

### Chip / ChipGroup
- Chip uses `aria-pressed` (toggle button) — NOT a radiogroup —
  because the brief lists multi-select use cases (Finishing, Delivery).
  If a future caller needs single-select chips, they can manage the
  `selected` state externally.
- Selected chip: `border-[var(--color-cyan-ink)]` +
  `text-[var(--color-cyan-ink)]` + `bg-[var(--color-cyan-ink)]/10`
  (10% cyan wash). No `--color-cyan-ink-soft` token exists in
  `globals.css`, so the opacity modifier is the cleanest way to get
  the tint without hardcoding hex.
- ChipGroup wires its visible label to the wrapping `role="group"`
  via `aria-labelledby` using a `useId`-generated ID.

### NumberStepper
- The input keeps a local `draft: string` so the user can clear the
  field or type intermediate digits ("3" while aiming for "35")
  without the parent clamping on every keystroke.
- Live-commit only when the parsed value is within `[min, max]` —
  out-of-range drafts wait for blur, where `commit()` clamps and
  syncs the draft. This avoids price-total flicker.
- ArrowUp / ArrowDown on the input step by 1, matching the native
  number-input affordance. Enter commits and blurs.
- `role="spinbutton"` + `aria-valuemin/max/now` on the input — AT
  announces it as a spinner, not a free text field.
- Buttons disable (not visually grey + still clickable) at the
  bounds — `disabled:opacity-40 disabled:pointer-events-none`.

### BottomSheet
- Rendered via `createPortal(... , document.body)`. SSR-safe: returns
  `null` when `typeof document === 'undefined'`.
- Focus management: on open, captures `document.activeElement`, locks
  body scroll (`overflow: hidden`), and moves focus to the first
  focusable element inside the sheet (or the sheet itself) via
  `requestAnimationFrame` to avoid a focus race with React's commit
  phase. On close, restores focus to the captured element.
- Focus trap: Tab and Shift+Tab cycle within the sheet. The trap
  finds the first/last focusable element via a `FOCUSABLE_SELECTOR`
  query and wraps focus accordingly.
- Escape listener attached with `capture: true` so it always wins
  over any child handler — Escape closes the sheet, period.
- Backdrop is a sibling of the sheet (not a parent), so clicks on
  the sheet can't bubble to the backdrop. `stopPropagation` on the
  sheet is belt-and-suspenders.
- Entry animation: `animate-in fade-in` (backdrop) and
  `animate-in slide-in-from-bottom` (sheet) from `tw-animate-css`
  (already imported in `globals.css`). Exit animation intentionally
  omitted — the sheet unmounts on close, keeping parent state and
  portal lifecycle in sync. `prefers-reduced-motion` is handled by
  the global rule in `globals.css` that flattens all animations.
- The wrapper has `role="presentation"` (the dialog itself carries
  `role="dialog"` `aria-modal="true"` `aria-label={title}`); the
  backdrop is `aria-hidden`.

## What's NOT in scope (hand-off notes for the next agent)

- These are leaf components — no integration into `page.tsx` or any
  route yet. The next flow task (likely P2.4 or P3.x) will compose
  them into the Files / Options / Pay screens.
- No unit tests written (per project policy: "do not write any test
  code").
- The `Stepper` is display-only. If the design lead later wants
  tappable steps for "go back to Options", wrap each `<li>`'s inner
  content in a `<button>` and add an `onStepClick?: (i: number) => void`
  prop.
- The `BottomSheet` has no drag-to-dismiss gesture — only the visual
  drag handle. Adding real drag-to-dismiss requires a pointer-events
  library or a hand-rolled `onPointerDown/Move/Up` handler; deferred
  until the design lead confirms it's needed (the iOS sheet gesture
  is notoriously fiddly to get right with momentum).
