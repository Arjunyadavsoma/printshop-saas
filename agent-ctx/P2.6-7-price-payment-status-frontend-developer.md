## Component-specific decisions worth noting

### price-breakdown.tsx
- `formatRupees(paise)` drops trailing `.00` so collapsed totals stay compact ("₹48", not "₹48.50" when there are no paise). Discounts (negative paise) render in `--color-success` green with a leading minus.
- Collapsed row is a `<button>` (not a div with onClick) for keyboard accessibility; `aria-expanded` + `aria-controls` wire the toggle to the detail region.

### payment-sheet.tsx
- Default UPI app list is `DEFAULT_APPS` (GPay, PhonePe, Paytm, BHIM, Other) but is overridable via the `apps` prop so shops with a preferred provider can reorder.
- Desktop QR is a framed placeholder showing the raw `upiUri` text under a `QrCode` glyph — the layout is honest about what's missing in dev. In production, callers pass a `qrUrl` image (server-generated via `/api/v1/dev/qr` or `/api/v1/qr`) — but PaymentSheet itself takes `upiUri` (the deep-link string), not the image URL, since the image generation is the host's concern. (Note: this differs slightly from the TokenSlip's `qrUrl` prop — PaymentSheet renders the URI text as a dev placeholder because the host typically swaps in a real `<img>` for desktop QR; TokenSlip renders an actual `<img>` when `qrUrl` is provided.)
- Copy button shows a 2-second "Copied" success state then resets, so the affordance reads as a tap rather than a stuck toggle.

### utr-input.tsx
- Controlled component: parent owns `value`/`onChange`. The formatted value (with spaces) is what's stored — parent strips spaces before sending to the API.
- Paste handler intercepts only when ≥12 digits are pasted (full UTR), to normalize + format in one shot without a double-change. Shorter pastes fall through to the normal change handler.
- `maxLength` is 14 (12 digits + 2 separator spaces) so the formatter never truncates.
- The hint slot is always rendered (a transparent placeholder `<p>` when empty) so the layout doesn't jump when validation state changes.

### status-timeline.tsx
- Connecting line is an absolutely-positioned `<span>` with `border-l-2`, omitted on the last step so there's no dangling line below "Collected".
- `done` steps show a `Check` icon instead of the number (the number is redundant once complete); `current` and `future` show the positional number.
- `sr-only` text announces "Completed" / "In progress" / "Upcoming" for screen readers, since the colour + check icon alone isn't a label.

### token-slip.tsx
- Pickup code is the HERO — `text-2xl font-bold tnum tabular-nums` centered, with a muted uppercase "Pickup code" label above. The QR is intentionally smaller (96×96) because at the counter the human-readable code is faster than a scanner.
- QR is a real `<img>` when `qrUrl` is provided; otherwise a same-footprint placeholder (`QrCode` glyph + "QR" caption) so the slip layout is stable in dev and on routes without a server-side QR.
- Receipt metadata uses `<dl>`/`<dt>`/`<dd>` semantics (term/value pairs) rather than divs.

### status-pill.tsx
- `pending` (amber) uses `--color-ink` text, NOT white — amber-on-white fails AA at the small pill size; ink-on-amber passes. All other statuses use white-on-colour (verified by the existing `scripts/validate-contrast.ts` baseline).
- `role="status"` is set on the pill so it's announced as a live region when used in dynamically-polling contexts (e.g. the order page). Harmless in static list rows.
- Default labels are exported as `STATUS_LABELS` so callers can align list-row copy with the pill text without duplicating strings.

### form-field.tsx
- Uses `cloneElement` to inject `aria-describedby` + `aria-invalid` onto the child input — the caller doesn't have to thread those props manually. Caller-supplied `aria-invalid` wins when no `error` is present (so the caller can mark a field invalid for non-error reasons if needed); `aria-describedby` is always the wrapper-derived value to keep the wiring correct.
- "Required" is the literal word "(required)" in muted text after the label — NOT a red asterisk (which is a generic-design tell and invisible to screen readers without an aria-label).
- When both `hint` and `error` are present, the hint is HIDDEN (only the error shows) to avoid redundant/conflicting messages; both ids are still listed in `aria-describedby` so a caller can re-show the hint elsewhere if desired.

## What this enables

These 7 components are the building blocks for the customer payment + order-status screens:
- The **order confirmation screen** composes `TokenSlip` (hero pickup code) + `StatusTimeline` (current step = Payment) + `PriceBreakdown` (trailing `StatusPill` = pending) + `StickyActionBar` (CTA = "Pay now").
- The **payment bottom sheet** hosts `PaymentSheet` (app buttons / QR + copy UPI ID) → on return, `UTRInput` captures the 12-digit reference, with `FormField` wrapping it for label/error semantics.
- The **order tracking screen** uses `StatusTimeline` (current step = Printing with `subProgress`) + `StatusPill` (printing) + `TokenSlip` (so the customer can re-show the code at the counter).

All components are pure/presentational (no API calls, no state machines beyond local UI state) so they can be composed into any screen without coupling.
