## Design decisions

### IndexedDB draft recovery — parallel to localStorage, not replacing it
The existing localStorage draft (`printshop:customer-draft`) silently restores on mount. The new IndexedDB layer (`printshop-drafts` DB) adds an **explicit** restore offer UI ("Resume your previous order?") which only surfaces when:
- A draft < 2h old exists in IndexedDB, AND
- The localStorage restoration did NOT happen (`files.length === 0`)

This way the two layers complement each other: localStorage handles the "refresh the tab" case silently, IndexedDB handles the "tab kill / pocket-call / private-mode" case with a clear prompt. The draft is cleared from BOTH stores on order placement.

The `useDraftRecovery` hook debounces saves by 500ms so rapid edits (toggling 30 page modes) don't thrash the DB. Each save is fire-and-forget — IndexedDB errors are swallowed because the order flow must never break on a persistence failure.

### Color suggestion prompt — two variants, one component
The brief says the prompt sits "ABOVE the page strip". The page strip only renders when Mix is selected. So I render TWO instances of `ColorSuggestionPrompt` in the Options step:

1. **Pre-Mix variant** — rendered ABOVE the preset cards, when the file has a suggestion with at least one colour page AND the customer hasn't picked Mix yet. "Accept" applies the suggestion (colour pages → 'colour', rest → 'bw') without opening the page strip. "Customize" picks the Mix preset (which opens the page strip).
2. **In-Mix variant** — rendered ABOVE the page strip, when Mix is selected and the suggestion has colour pages. Both buttons dismiss the prompt; "Accept" also applies the suggestion.

Both variants track dismissal per-fileId in a `Set<string>` state so the prompt never nags the same file twice. The "don't nag" rule is enforced by the parent (the component itself is stateless).

### Analytics — privacy-first, fire-and-forget
- **No third-party trackers** — no GA, no Mixpanel, no Meta pixel. Events go to our own `/api/v1/analytics/track` endpoint.
- **No personal data** — the `track()` function accepts any properties, but the call sites only send anonymous ones: `shop_slug`, `page_count`, `preset_name`, `amount_paise_range` (bucketed into `<10 / 10-50 / 50-100 / 100-500 / 500-1000 / 1000+`), `colour_page_count`, `app_id`, `source`. The `amountPaiseRange()` helper buckets the order total. Phone numbers, file names, and UTR values are NEVER sent.
- **Fire-and-forget** — `track()` never throws, never blocks. All failures (network down, IndexedDB unavailable, JSON errors) are silently swallowed.
- **Batched** — events queue in localStorage (max 100, FIFO), flush every 30s OR when 20 events accumulate. `keepalive: true` on the fetch lets the request outlive the page. On network failure the batch is re-queued at the front so events retry on the next flush.
- **SSR-safe** — `track()` is a no-op when `typeof window === 'undefined'`, so it can be imported anywhere without guarding each call site.

### Last choices — Mix is NOT remembered
`saveLastChoices` stores whatever preset the caller passes (including 'mix'). `loadLastChoices` normalises 'mix' → 'notes' on read, because Mix is file-specific (the colour page selection depends on which pages of which file are colourful). Returning customers get a sensible default (Notes B&W) instead of being forced into the Mix page strip.

Saved on two occasions:
- When the customer picks a preset (in `pickPreset`) — only for non-Mix presets.
- When the order is placed (in `place()`) — captures the active file's options.

Applied on one occasion:
- When the first file becomes READY (in a `useEffect`) — if the customer (or a restored draft) hasn't already picked a preset for that file.
