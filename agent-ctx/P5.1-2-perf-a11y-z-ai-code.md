## Detailed change log

### 1. Route-level code splitting (Task 1)

**File:** `src/app/s/[shopSlug]/page.tsx` — Server Component.

Replaced the static `import { CustomerOrderFlowV2 } from './CustomerOrderFlowV2';` with a `next/dynamic` import that ships `ssr: false` + a loading skeleton:

```typescript
import dynamic from 'next/dynamic';
import { CustomerFlowSkeleton } from './CustomerFlowSkeleton';

const CustomerOrderFlowV2 = dynamic(
  () => import('./CustomerOrderFlowV2').then((m) => m.CustomerOrderFlowV2),
  {
    loading: () => <CustomerFlowSkeleton />,
    ssr: false,
  },
);
```

**Why:** `CustomerOrderFlowV2.tsx` is a ~1900-line client component (upload chunking, page strip, payment sheet, draft-recovery, IndexedDB). Server-rendering it would have meant serializing the entire flow into the initial HTML + JS payload for `/s/[shopSlug]`, even though the customer only needs the AppBar + rate-board + live "printers online" line on first paint. Splitting it out lets the shop landing ship the light SSR shell instantly while the heavy flow chunk downloads + hydrates in parallel — the customer sees a stable skeleton, not a flash of empty content.

**New file:** `src/app/s/[shopSlug]/CustomerFlowSkeleton.tsx` — a server component (no `'use client'`) that mirrors `CustomerOrderFlowV2`'s step-0 layout: stepper row, upload dropzone, file-card placeholder, preset row, and a sticky action bar at the bottom. Uses the existing `SkeletonBox` / `SkeletonText` primitives from `@/components/customer/skeleton` so the shimmer matches the rest of the app. `aria-hidden="true"` on the root — the skeleton is decoration for sighted users; a screen-reader user hears the server-rendered "N printers online…" line until the real flow hydrates.

**Note on Next.js 16 + `ssr: false`:** `next/dynamic` with `ssr: false` was deprecated in Next 15.0 inside Server Components, then **re-enabled** in Next 15.1+. We're on Next 16.1.3, so this pattern is fully supported. Verified by `bun run typecheck` (no error in this file) and `bun run lint` (clean).

### 2 + 6. Reserve price min-width + add `aria-live` (Tasks 2 & 6)

**File:** `src/components/customer/sticky-action-bar.tsx`.

Both changes apply to the same `<p>` element that renders the live total — folded into one edit.

**Before:**
```tsx
<p className="text-xl font-semibold text-[var(--color-ink)] tnum leading-tight">{total}</p>
```

**After:**
```tsx
<p
  className="text-xl font-semibold text-[var(--color-ink)] tnum leading-tight min-w-[80px]"
  aria-live="polite"
  aria-atomic="true"
>
  {total}
</p>
```

**Why:**
- `min-w-[80px]` — When the price widens (e.g. `₹48` → `₹124`), the digit count grows and the price element grows horizontally. Without a reserved width, the CTA button on the right would shift left/right as the price updates, causing layout shift on every page toggle. 80px covers up to four characters of tabular-numerals at `text-xl` + the rupee glyph + the "Updating…" state.
- `aria-live="polite"` — When the customer toggles a page mode, the live total updates. Without an `aria-live` region, a screen-reader user has no way to know the price changed unless they re-navigate to the bar. `polite` priority announces the new total without interrupting whatever is being spoken.
- `aria-atomic="true"` — Ensures the region announces the WHOLE value each time (e.g. "Total ₹124") rather than just the diff ("24"), which would be meaningless without the currency symbol.

### 3. Debounce quotes + AbortController (Task 3)

**File:** `src/app/s/[shopSlug]/CustomerOrderFlowV2.tsx`.

The existing quote request was already debounced via `setTimeout(QUOTE_DEBOUNCE_MS)` with `QUOTE_DEBOUNCE_MS = 400` (confirmed in `src/app/s/[shopSlug]/CustomerOrderFlowV2.tsx:120`). What was missing: an `AbortController` to cancel stale in-flight requests.

**Added:**
1. New ref: `const quoteAbortRef = useRef<AbortController | null>(null);` next to the existing `quoteTimer` ref.
2. Inside the `useEffect` that builds + fires the quote request:
   - At the top of each effect cycle, if `quoteAbortRef.current` exists, abort it (`quoteAbortRef.current.abort()`) — this kills the previous in-flight fetch so its stale response can't race the freshest one.
   - Create a fresh `AbortController` per cycle, store it on the ref.
   - Pass `signal: controller.signal` to `fetch(...)`.
   - In the `catch` block, swallow `DOMException` `AbortError` (expected when a fresher cycle supersedes this one — surfacing it as a customer-facing error would be wrong).
   - In the `finally` block, only clear the `quoting` spinner state if this controller is still the active one (`quoteAbortRef.current === controller`). If a newer cycle has already started (and set `quoting=true` again), clearing it here would briefly hide the spinner.
   - In the effect's cleanup function (re-runs when `quoteKey` changes or the component unmounts), abort the in-flight request so we never leave a dangling fetch that could resolve after the customer navigates away.

**Why:** Without this, rapid page toggles could fire multiple quote requests in parallel. The last one to land would set the price — but if request N completes after request N+1, the customer would see the price for the OLD selection, not the current one. AbortController guarantees only the freshest request's response can land.

### 7. BottomSheet focus management + `aria-labelledby` (Task 7)

**File:** `src/components/customer/bottom-sheet.tsx`.

Verified the existing focus management is correct:
- **Focus trap:** `onKeyDown` handler on the sheet catches `Tab` + `Shift+Tab`, finds the first/last focusable elements via `FOCUSABLE_SELECTOR`, and wraps focus. ✓
- **Focus restore:** `previouslyFocused` ref captures `document.activeElement` on open; the cleanup function calls `previouslyFocused.current?.focus()` on close. ✓
- **Body scroll lock:** `document.body.style.overflow = 'hidden'` on open, restored on cleanup. ✓
- **`role="dialog"` + `aria-modal="true"`:** already present on the sheet `<div>`. ✓

What was missing: **`aria-labelledby` pointing to the title.** The original used `aria-label={title}`, which duplicates the title as a string attribute rather than pointing AT the visible heading element. The WAI-ARIA dialog pattern prefers `aria-labelledby` so screen readers announce the same heading the sighted customer sees (and so the heading's id is programmatically associated with the dialog).

**Changed:**
1. Added `useId` to the React import.
2. Generated a stable hydration-safe id: `const titleId = useId();`
3. Replaced the dialog's `aria-label={title}` with `aria-labelledby={title ? titleId : undefined}` (and a fallback `aria-label="Dialog"` when no title is passed — the dialog still needs an accessible name in that case).
4. Added `id={titleId}` to the `<h2>` title element.

The `useId()` hook generates a value like `:r1:` that's stable across server + client renders, so the label association survives SSR hydration.

   ```css
   }
   ```
   The page-flip animation is replaced with a 100ms opacity fade — still provides visual feedback that the toggle registered, just without the Y-axis rotation that would trigger motion sickness.

2. **Global rule** (lines 409–416):
   ```css
   @media (prefers-reduced-motion: reduce) {
     *, ::before, ::after {
       animation-duration: 0.01ms !important;
       animation-iteration-count: 1 !important;
       transition-duration: 0.01ms !important;
       scroll-behavior: auto !important;
     }
   }
   ```
   This flattens ALL animations + transitions across the app — the bottom-sheet slide-in, the skeleton shimmer, hover/focus transitions, the back-to-top scroll, everything. The `!important` ensures it wins over any per-component animation utility class (e.g. `animate-in slide-in-from-bottom`).

### 10. `axe-core` + axe-check script (Task 10)

**Files:**
- `package.json` — added `"axe-core": "^4.14.0"` to `devDependencies` (it was previously only a transitive dep of `@axe-core/playwright`; making it direct ensures the type imports in `axe-check.ts` resolve under strict `bun install --frozen-lockfile` and pnpm strict-node-layout CI).
- `src/lib/test/axe-check.ts` (new) — the helper module.

**Helper exports:**
- `DEFAULT_A11Y_TAGS` — `['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa']` — the WCAG 2.x A + AA including 2.2 AA tag set the project targets (matches the existing `tests/accessibility.spec.ts` config).
- `DEFAULT_EXCLUDE` — `['#toast-region']` — the Sonner/toast portal that lives outside the React tree and produces false-positive `aria-allowed-attr` violations on transient toast clones.
- `formatViolations(violations)` — pretty-prints axe violations as a multi-line string (rule id, impact, help URL, affected selectors) so the Playwright reporter surfaces actionable failures, not "expected [] to equal []".
- `runAxeCheck(page, options?)` — the main entry point. Builds an `AxeBuilder` with the default tags + excludes, calls `.analyze()`, filters by impact if `seriousOnly` is set, and throws an actionable error if there are violations. Returns the full `AxeResults` so callers can do additional assertions.

**Usage:**
```typescript
import { runAxeCheck } from '@/lib/test/axe-check';

test('shop landing has no WCAG violations', async ({ page }) => {
  await page.goto('/s/quickprint');
  await runAxeCheck(page, { label: 'shop landing' });
});
```

**Design notes:**
- The helper is a TypeScript module (not a `.test.ts` file), so Vitest won't try to execute it (vitest.config.ts `include` is `['packages/**/*.test.{ts,tsx}', 'src/**/*.test.{ts,tsx}']` — `axe-check.ts` doesn't match).
- It's only imported by Playwright tests under `tests/`, so Next.js's bundler never traverses it during route compilation — the `@playwright/test` + `axe-core` dev-only imports don't leak into client/server bundles.
- `.gitignore` change: the existing pattern `test` was over-broad — it matched any file or directory named `test` anywhere in the tree, which silently ignored `src/lib/test/`. Changed it to `/test` (anchored to repo root) so the helper stays tracked while still ignoring any future top-level `test/` artifact dir. There's no existing top-level `test/` directory in the repo, so this is a no-op for the existing tree.
